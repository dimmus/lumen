- **The idiom**: `*std::format_to_n(dst, sizeof(dst) - 1, "...", args).out = '\0';` reproduces snprintf's truncation + guaranteed NUL exactly (precedents: `diagnostics.cppm` addf, `clipboard.cpp`). Append chains read the untruncated length from `format_to_n_result::size` (snprintf's return contract) and still terminate each segment. `%g`→`{:.6g}` and `%.2f`→`{:.2f}` verified byte-identical to printf over 23 + 18 representative doubles before converting (test programs, not assumption). `%.61s`→`string_view::substr(0, 61)`; run-time-chosen format strings (`"%.2f/%.1f/%.0f"` ternary in `inputs.cppm`, `"%u application(s)"` in launcher) become literal branches/plural `{}` — a ternary of literals is not a constant expression for `format_string`.
- **Traps when scripting this** (all hit, all fixed before commit): (1) `n = std::snprintf(...)` regex-rewritten to `n = *std::format_to_n(...).out = '\0'` silently sets `n = 0` — it compiled and would have made both `cache_dir()`s (`ui_gl.cppm`, `ui_vk.cppm`) always return false with XDG_CACHE_HOME set, disabling the program caches; the correct form assigns `n = seg.size`. (2) A leading `(void)` discard collides with `*...out = '\0'` ("assignment to cast is illegal"). (3) `{:02u}` is invalid — std::format has no `u` presentation type; unsigned decimal is `{:02}`. (4) Placeholder-count mismatches surface as "call to immediate function is not a constant expression", not as a clear format error. Audit every scripted site for null `char*` args: glibc `%s` printed `(null)`, `{}` is UB.
