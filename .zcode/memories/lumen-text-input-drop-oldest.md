**Why:** restructuring a byte buffer with memmove means overlapping moves, and the safe order is derived from destination intervals, not habit — moving the later region first clobbers an earlier region's source exactly when an eviction bump pushes `take` below `evict_before`. And a green suite proves nothing about corners no test reaches: silent byte-level text corruption passed 141/141.

**How to apply:** when inserting+evicting in one buffer, write the two moves in destination order (prefix first here) and derive disjointness on paper — state each dest/source interval before writing the comment. Pin multi-byte straddles with BOTH shapes (2-byte char mid-text and a 3-byte char under a 1-byte selection, non-empty prefix AND suffix) — ASCII tests and caret-at-end cases cannot catch it. Never let a caller re-index with `size() - before` when a policy can shrink; hand it the span out-param. Before trusting "green" over a raw-memory change, ask which case exercises the eviction bump with survivors on both sides.
