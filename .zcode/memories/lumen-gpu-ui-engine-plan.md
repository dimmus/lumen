The plan is `docs/adr/010-gpu-ui-engine.md` on main (merged 2026-10-22 as dimmus/lumen#31 from branch `claude/lumen-gpu-ui-engine-6e3306`). The survey facts below predate this work.

Decisions in it: one primitive renderer (GPUI's seven kinds: quad/shadow/mono_sprite/poly_sprite/path/underline/surface, 80/64/64/48 B instances, (order, kind, page) batching with an allocation-free overlap grid) in `lx.gfx` for compositor chrome, lumen-shell and lx.app clients; Vulkan + GLES 3.1 + CPU backends; client windows render into dmabuf swapchains with linux-drm-syncobj explicit sync; damage + buffer age partial redraw; zero steady-frame heap allocation as a gate; UI surfaces blend in sRGB-encoded space (GPUI's look) while the compositor keeps linear-light window compositing; Zed theme JSON compiled by `tools/lumen-theme`; One Dark/One Light tokens, elevation shadows, spacing (b00–b48), 14 px UI text on a 16 px rem, line height φ, radii xs 2/sm 4/md 6/lg 8 px, IBM Plex Sans + Lilex fonts, Lucide icons. Six phases, gates G1–G11, bench `lumen-ui-bench` + `scripts/ui-bench.sh` with JSON baselines and CTest label `bench`.

Survey facts (verified 2026-10-22): lx.ui emits only textured quad + solid fill and `draw_scope::fill` never sets `draw_command::solid`; no executable publishes lx.ui output; lumen-shell paints with CPU `shm_canvas`; lx.wayland.client and lx.app are stubs; lx.text is single-face single-line; `glyph_atlas.cppm` is a stub; Vulkan compositor uses push constants per draw, no damage, no VkPipelineCache; `LX_TRACE_SCOPE` cannot be used twice per scope; `end_tick_render` never called; host exposes GLES 3.1 on SVGA3D; fribidi and libunibreak installed; compositor already serves zwp_linux_dmabuf feedback and linux-drm-syncobj.

**Why:** The ADR is the agreed plan; a session that starts implementation should read it instead of re-surveying the same ground, and the survey facts above say which stubs it will replace.

**How to apply:** Implementation work should start from Phase 0 of the ADR and keep its gates; re-read the ADR before changing primitive layouts or theme decisions. Related: [[lumen-host-build-run-env]], [[lumen-best-in-class-bar]].
